The first call is unpaid. It's for scoping, and the build itself is quoted separately. The call exists so we both picture the same first version and I can send a quote that matches it.

Bring whatever you have. A long spec is fine, and so is a voice note or a line like "something like X, for Y people." If you have a spec, we'll work from it, and we'll still need to agree which parts go into the first version.

What I'm listening for is simpler than a full requirements document:

- Who it's for
- What they need to get done
- What you already have (copy, a brand, data, a half-built repo)
- What "working" means in a few weeks, rather than in a year

I write that back to you as a scope, then a quote. Paid work starts when you accept the quote.

The call is useful even if the idea is still vague. Usually we leave with a smaller and clearer description than we started with. Sometimes we find it's too early to build, which is worth knowing before anyone spends money. What gets expensive is starting a build on a description neither of us could repeat back.
